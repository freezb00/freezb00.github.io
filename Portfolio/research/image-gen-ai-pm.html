01 核心结论（5 条）

核心 Thesis 判断系统

TL;DR — 图像生成 AI PM 的核心不是「调 Prompt」，而是把 抽卡式生成 产品化为 可控工作流：美学 Eval + 安全校准 + 版权策略 + 分辨率×步数算力经济。2025-2026 行业分水岭：从「模型炫技」→「导演工作台」（分镜/角色卡/版本回溯/一致性）。与通用 AI PM 比，多了 视觉质量分布、LoRA/风格体系、NSFW 校准、IP 诉讼风险；与设计工具 PM 比，多了 概率输出、生成成本、模型选型。专业交付三件套 (Deliverables)：Aesthetic Rubric + Safety Policy + Workflow Demo（非单张效果图）。

结论 1

2025-2026 图像 PM 的第一职责是「工作流产品化」，不是「堆模型能力」

行业从 Prompt 驱动「抽卡」转向分镜编辑器、角色/场景资产卡、局部重生成、版本回溯——把导演结构化流程拆成产品模块。Seedance 2.0、PixMax、爱奇艺纳逗 Pro 均指向同一逻辑：可控性 > 单次生成画质。
[B1] woshipm《从抽卡到可控》；[B2] 今日头条 Seedance 2.0 分析

结论 2

Eval 体系是图像 PM 的「定义性技能」，且与 LLM Eval 完全不同

不能只用 FID/CLIP；需分层：Prompt Adherence、Aesthetic Appeal、Text Rendering、Domain Accuracy、Safety。Qwen-Image-Bench 五柱（Quality / Aesthetics / Alignment / Real-world Fidelity / Creative Generation）；Gecko 证明细粒度 VQA 模板比 Likert 更稳定。
[A1] Qwen-Image-Bench arXiv；[A2] Gecko arXiv 2404.16820

结论 3

安全过滤器「松紧」是 PM 决策，不是工程默认

三层栈：Input 过滤 → In-model guardrails → Output classifier。太严合法用例失败，太松 NSFW/Deepfake/版权角色泄漏——Midjourney 已被 Disney/Universal/WB 联合起诉，诉状指其「已有暴力/裸体过滤技术但未用于版权角色」。
[B3] Institute PM Diffusion Guide；[A3] Disney v. Midjourney 诉状 CourtListener

结论 4

C 端 vs ToB 图像 PM 是两种职业路径

C 端（Midjourney/即梦/可灵）：社区审美、订阅、风格探索、抽卡体验优化。ToB（Adobe Firefly/Canva AI）：品牌一致性、合规、工作流嵌入、enterprise governance。即梦走「闭环」（DeepSeek 写词→生成一体），可灵走「下沉+API」。
[B4] woshipm《可灵下沉 vs 即梦闭环》；[A4] Adobe Firefly PM JD

结论 5

图生视频是图像 PM 的自然延伸，但 Eval 维度翻倍

新增：时序一致性、运动物理、角色跨帧 ID、时长×帧率算力。视频质量仍落后图像 2-3 年；PM 应设 3-10 秒 clip 为 MVP 边界，而非追 Sora 级长片。[待确认]
[B3] Institute PM — "Video 2-3 years behind image"；[B5] woshipm OiiOii Agent 工作流

虚拟试穿人脸/体型 identity 不变服装贴合度、阴影

6.2b Red Team 与 NSFW（PM Owner）

2025 研究：文本过滤 ≠ 安全。DALL·E 3 / Imagen 3 经 rewrite 攻击后 NSFW 成功率可从 0 升至 44%+（context shift）。PM 需组织 Red Team sprint，每次 major model version 必跑。

攻击类别PM 动作
Explicit NSFWBlocklist + 输出 classifier
Implicit / 隐晦意图Semantic classifier（非关键词）
Context shift 组合绕过Red team seed 库 + 多阶段检测
版权/IP trigger风格/角色 blocklist + 相似度检测
图生图链式攻击Inpaint 输入校验 + 输出二次扫描

[A6] OpenReview Red-Teaming NSFW Classifiers

6.2c 成本优化决策（研发级）

ICCV 2025 PostDiff 结论：高保真场景下，减每步成本（mixed-resolution） 往往优于 naive 减步数。PM 应优先评估 Prompt 路由 + 两阶段超分，而非全局 50→20 步。

策略适用质量影响成本影响
减步数 50→20草稿/预览中-高线性↓
Turbo/Distilled实时/批量中50-80%↓
低分→超分两阶段4K 交付低-中40-70%↓
Prompt 复杂度路由多 tier 产品按 slice 优化全局最优

[A7] PostDiff ICCV 2025；Cost-Aware Routing arXiv 2506.14753

12 立场对照

挑战 1：「图像 PM = 设计师转岗」不完全对 — 设计师转岗缺 Diffusion Eval、算力经济、Safety 校准；纯算法 PM 转岗缺审美 rubric 与创作 workflow 理解。最优仍是 T 型：产品 + 视觉 taste + Diffusion 通识。

挑战 2：「工作流 > 模型」有边界 — 当基础模型 leap（如角色原生一致性），薄编排层价值会被压缩（OiiOii 类风险）。PM 需同时 bet workflow 深度与 model 升级窗口。

挑战 3：开源 vs 闭源 PM 技能不通用 — SD/FLUX 生态 PM 需懂权重/LoRA/ComfyUI；Midjourney/DALL·E PM 需懂 API 限制与 policy。产品需对齐公司业务模式。

挑战 4：美学 Eval 主观性无法完全消除 — Human preference 仍是 gold standard；自动化 metric 仅作 regression 辅助，不能替代 launch gate 人工评审。

行业与工程落地建议 (Actionable Recommendations)

  • Portfolio 三件套：① Aesthetic Rubric + 20 条 golden prompt eval ② Safety policy 样例 ③ Workflow teardown（即梦/可灵/MJ 选一）
  • Go/No-Go 标准答法：Hard Gate → offline metric on fixed set → slice regression → human A/B → red team pass rate → cost SLA
  • 典型业务决策推演：「FID 很好但设计师说变差」→ 拉 slice，查 gate pass rate，品牌 slice 降则拒上线；「50 步→20 步省 60% 成本做不做」→ 看 gate + HPSv2 + 考虑路由/减每步成本
  • 边界口诀：PM 定标准，算法达标准，设计师定审美锚点，审核员守最后一道门
  • 必会术语：CFG、Steps、LoRA、Inpainting、ControlNet、Temporal Consistency、HPSv2、Hard Gate
